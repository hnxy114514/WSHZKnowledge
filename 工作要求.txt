对助手的工作要求（持续更新）

==================================================
一、数学公式与渲染
==================================================
1. 数学符号全面规范化：分数写成上下结构（不是 a/b 斜杠），
   上下角标用 ^{} _{ }，所有数学符号都要规范，正文和配图都要。
2. 复杂分式、根号参考网上成熟方案实现；根号的「勾」和顶部横线
   必须连成一体，比例随内容伸缩，不能勾大横线小、不能分离。
3. 向量要正常显示为字母上方箭头。
4. 分式不能穿模：分子下缘、分母上缘都不能压到分数线。
5. 返回键随列表滑动改变位置，不固定占顶部空间，尽量利用屏幕。

==================================================
二、内容与数据
==================================================
6. 重点高亮必须人工判断哪里是重点，不能用代码规则批量标注；
   可以是某个词、某个字非常重要就高亮它。
7. 知识点列举不完整的地方要补完整。
8. 补充包要融合成分科目源文件，用缩进判断结构（TREE 嵌套）。

==================================================
三、代码质量
==================================================
9. 删除死代码、过时注释。
10. 清理「AI 味很重」的注释（不是乱码，是那种冗余的 AI 式废话注释）。
11. 项目要有体系，不能乱七八糟；目录结构、文档、构建发布流程要清晰。

==================================================
四、更新与发布
==================================================
12. 用 GitHub 实现云端更新。
13. APK 也要上传，用 GitHub Releases 发布、提供直链下载。
14. 更新方式用 APK 覆盖安装，不用 update.json 文字更新。
15. 下载更新前先申请「安装未知应用」权限。
16. 下载安装包用「临时文件 + 重命名」，防止重复下载时装到旧包。
17. 每次做完内容/代码改动后，上传 GitHub 并发布新 Release 方便更新。
18. 版本号用语义化三段 X.Y.Z：
    - 第 1 位：非常大的结构性改动
    - 第 2 位：资料库新增内容（知识点、配图、高亮等）
    - 第 3 位：功能新增、界面调整、修 bug（小功能也走这一位）
    不要用 14、15、16 这种一直加一的版本号。

==================================================
五、协作方式
==================================================
19. 用中文思考和回答。
20. 每次改动后要检查、验证，不能改出更大的 bug。
21. 定期做工作总结：把「已做好」和「之后还要做」列清楚，节省上下文。
22. 应用图标重新设计过（深紫渐变 + 打开的书 + 金色根号）。

==================================================
六、环境与凭据
==================================================
23. GitHub Token 90 天有效，可以一直用，不要反复提醒撤销。
24. 签名密码、GitHub Token 都不能写入仓库或文档，通过环境变量传入。
