背单词 + 单词搜索 · 方案

针对「腕上知识汇总」Wear OS 端 ｜ 词库来源 kajweb/dict ｜ 2026-11-26

结论：可以做，而且不会像上次优化知识库那样踩坑。

三张主力词表（四级 + 六级 + 考研）去重后 4441 词，精简到 0.66 MB。 启动时只读一份 60 KB 的索引，查词时按位置读几百字节—— 不是"启动解析全部"，而是"用到才读一条"， 所以对启动速度没有影响。

一、词库实测

精简口径：词 + 音标 + 最多 3 条词性释义 + 1 条例句（中英）。原始字段里的 syno（近义词）、relWord（同根词）、phrase（短语）、 realExamSentence（真题例句）、音频字段全部丢弃——它们占了 90% 的体积， 手表上根本看不完。

全量（81 个词表）是什么量级

含雅思、托福、GRE、SAT、GMAT、BEC、人教中小学系列。按单表平均 2500 词、去重后估约 2.2～2.8 万词，按同样的口径精简后约 3.5～4 MB。 这个体量不建议塞进 APK，也没必要——一个人不会同时背四级和 GRE。

二、数据怎么存

三段时间布局，一个文件 words.bin：

┌─────────── 头部 32 B ───────────┐
│ magic "HZW1" · 版本 · 词数 · 各段偏移 │
├─────────── 索引区（常驻，60 KB）───────────┤
│ 按字母序排列，每词 12 字节：                │
│   wordOff(4)  recOff(4)  recLen(2)  flags(2) │
├─────────── 正文区（按需 seek，1.2 MB）───────────┤
│ 变长记录，字段以 \u0000 分隔：                │
│   词 \0 音标 \0 释义 \0 例句英 \0 例句中      │
├─────────── 中文倒排（可选，0.4 MB）───────────┤
│ 释义二元组 → 词 ID 列表（查中文用）           │
└──────────────────────────────┘

启动时

只读头部 + 索引区，60 KB 顺序读，建一个 String[] 加两个 int[]， 约 5～10 ms。不解析任何释义，不建任何对象树。

查一个词

二分找到下标 → 按 recOff/recLen 定位 → 读几百字节 → 拆成 4 个字符串。 一次 RandomAccessFile.seek，1～3 ms。

和知识库缓存的区别：知识库那 1914 个节点是"列表要显示全部、搜索要扫全文"，必须全量建对象； 单词页一次只看一个词，所以只需要索引。 这次是真正的"用到才读"，不是把延迟藏起来。

三、背单词怎么算

用 SM-2（SuperMemo 2，Anki 的老算法）。不选 FSRS 是因为它参数多、要调，收益在手表这个体量上看不出来。

每个词记 8 字节

ease:     uint8   // 易度 ×100，默认 250（即 2.5），下限 130
interval: uint16  // 当前间隔（天），0 表示还没学过
due:      uint16  // 到期日，相对打包日的天数（够用 180 年）
reps:     uint8   // 连续答对次数
flags:    uint8   // bit0=已收藏  bit1=已在错词本

5000 词 × 8 字节 = 40 KB，整块读写，保存一次几毫秒。 不需要数据库。

三档评分（手表上就三个按钮，多一个都嫌挤）

按钮q 值效果
认识5间隔按 1 → 6 → interval×ease 递增
模糊3间隔不涨，ease 略降，明天再来
不认识1reps 归零，间隔回到 1 天，本轮内再出现一次

每日节奏：新词 10 个（可调 5/10/20）+ 到期复习，总数上限 60。 一天没背，第二天不惩罚，到期词顺延——手表上不要制造焦虑。

四、搜索怎么做

英文：前缀 + 精确

索引本身就是按字母序的，二分定位前缀起点，向后扫到前缀结束，取前 20 条。5000 词的二分是 13 次比较，可以忽略。

中文：倒排（二期）

释义里出现的每个中文二元组建倒排，如「取消」→ [cancel, abolish]。约 0.4 MB，查"取消"能出对应英文。

手表输入是真正的难点，不是搜索算法

Wear OS 上的输入法：语音（最实用）、手写、全键盘（极小）。方案是 EditText 唤起系统输入法，默认走语音；同时提供"按首字母浏览"作为降级—— 从 A 到 Z 选一个字母，列出该字母开头的词，适合"想看看这词怎么拼"的场景。 不自己做键盘，投入产出比太低。

五、界面与入口

新增四个屏：S_WORD_HOME / S_WORD_STUDY / S_WORD_DETAIL / S_WORD_SEARCH。 沿用现有的页面懒建机制（首次进入才建），圆屏底部内容调 padInner()， 卡片宽度按圆的弦长收窄——和问 AI 底部按钮用的是同一套几何。

入口放哪

  • 设置页加一行「背单词」——最省事，但藏得深。
  • 主页加一张卡——醒目，但主页现在是"九个科目"的知识库入口，混进一个工具会破坏定位。
  • 折中：主页底部一行小字入口（像现在的「按科目 / 按收藏」切换），不占卡片位。

六、分期

MVP（一轮做完，可测）

预处理脚本 tools/build_words.py（zip → 精简 → words.bin）· 四个屏 · SM-2 · 英文前缀搜索 · 进内测包。
验收：能背 20 个词、能搜 can→cancel、杀掉进程重开后进度还在、启动时间不掉。

二期

多词表切换（词表放云端，用户按需下载，APK 不膨胀）· 中文释义倒排搜索 · 错词本 · 学习统计（连续天数、完成率）。

三期（可选）

例句发音（依赖有道音频接口，可用性未知，先不做）· 每日提醒（需要手表通知权限）· 导入自定义词表（背课文里的生词）。

七、必须说清的风险

版权：这个仓库没有 LICENSE

kajweb/dict 的 README 写明「Crawl from X 道背单词」，仓库里没有 LICENSE 文件。 自己背、自己用，风险很低；但如果这个 App 要分发给别人，词库内容属于第三方版权， 严格说需要授权。

可替代：skywind3000/ECDICT（MIT 许可，约 340 万词条，含音标、释义、词频、柯林斯星级）， 体积大但可裁剪到同样规模。缺点是例句和释义措辞不如有道那套自然。 我的建议是把词库做成可替换的输入：预处理脚本吃哪个源都行， MVP 先用 kajweb 把功能跑通，分发前再切 ECDICT。

体积与定位

APK 从 3.2 MB 涨到约 4.1 MB（词库 0.66 MB + 索引 0.05 MB + 中文倒排约 0.25 MB）。 如果改成"首次使用时下载词表"，APK 只增 0.05 MB，但要考虑下载失败的兜底。

八、需要你定的四件事

1. 词表范围　只做四级+六级+考研（4441 词 / 0.66 MB），还是把雅思托福也打包（约 1.5 万词 / 2.3 MB）？
2. 数据放哪　打进 APK（离线可用、免下载），还是首次进入时从云端下载（APK 不变）？
3. 入口位置　设置页里一行，还是主页底部加个小入口？
4. 版权取舍　先用 kajweb 把功能做出来（个人用），还是从一开始就用 ECDICT（可分发）？

实测数据来自本轮下载的 4 个词表（CET4_1 / CET4_3 / CET6_3 / KaoYan_3）， 按「词 + 音标 + 3 条释义 + 1 例句」的口径统计。 词数、体积都是实数，不是估算；只有「全量 81 表去重后 2.2～2.8 万词」是按单表均值推算的。
